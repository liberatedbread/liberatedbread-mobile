# TED 5000 (The Energy Detective) — Research Notes

## What it is
TED 5000 series (Energy Inc., Charleston, SC), sold ~2008–2015: an MTU in the
breaker panel measures both legs and sends data over **powerline (PLC)** to an
Ethernet **Gateway**, which stores history and serves the "Footprints" web app.

## Why it's abandoned
- Retailers list the TED 5000 as discontinued with no direct replacement
  (ITM Instruments; Global Test Supply, retrieved 2026-08-07).
- Energy Inc. support told a user "we no longer support this product"
  (HA community thread 330407, 2021-08).
- Company itself is alive, selling the TED Pro line — so firmware/OS
  bit-rot (Flash-era Footprints UI) is the real enemy, not a cloud shutdown.

## Local API — vendor-documented third-party API
Energy Inc. published a "TED 5000 API" document for third-party apps; the
Gateway serves XML over HTTP on port 80:

- `GET /api/LiveData.xml` → per-MTU live power (W), voltage, and cumulative
  energy. This is what Home Assistant's core `ted5000` integration polls
  (local_polling).
- `GET /api/DashData.xml?T=0&D=0&M=0` → dashboard values incl. averages,
  projections, cost.
- History: `/history/hourlyhistory.xml?MTU=1&D=..&M=..&Y=...` (and daily/
  monthly variants) → recorded series.
- Auth: optional gateway admin password (default admin/1234 on stock units).

No cloud was ever required — the optional Google PowerMeter posting died with
PowerMeter in 2011 and the units kept working locally.

## Caveats
- MTU↔Gateway hop is powerline, not WiFi: PLC reliability varies by house
  wiring (long-documented pain point, staze.org 2020; nuxx.net teardown 2011).
- Footprints UI used Flash/Java in places; the XML API avoids all of it.
- MTU/Gateway firmware is frozen; treat as-is.
