# Lumo Lift — Research Notes

Posture trainer / activity clip by Lumo Bodytech (2014). Small sensor worn under the
shirt with a magnetic clasp; vibrates when the wearer slouches. Category: posture trainer.

## Why it is abandoned
- Lumo Bodytech's IP was acquired by Seismic (ex-Superflex) in Aug 2018 and the
  consumer posture business was wound down — [Just Style, 2018-08-21](https://www.just-style.com/news/superflex-rebrands-acquires-lumo-bodytech/).
- Apps are unsupported and hardware long gone from retail — [SitSense, 2026-01-17](https://www.sitsense.app/lumo-lift-discontinued).
- Lumo Run (smart shorts) and Lumo Back share the same app/platform family.

## Local BLE feasibility
- Device is a BLE peripheral; app talks to it over GATT. The coaching vibration runs
  on-device (double-press toggles coaching, per the CNET review), so posture feedback
  works with no phone at all; BLE is only needed for stats sync and configuration.
- No cloud dependency is required for the core function; account login exists in the
  app but coaching/tracking is local.
- **Verdict: viable local-only target.** No prior community RE found — greenfield.

## BLE UUIDs (recovered from static pass)
All custom UUIDs are generated by `LBDeviceProfile.customUUID(int)` as
`af12%04x-31d4-48e8-a1f8-5c09c020ae42` (`LBDeviceProfile.java`):

| int | UUID | Role |
|-----|------|------|
| 257 (0x0101) | `af120101-31d4-48e8-a1f8-5c09c020ae42` | LumoLift primary service (scan filter in `LKSensorMgr.java`) |
| 4097 (0x1001) | `af121001-31d4-48e8-a1f8-5c09c020ae42` | Activity characteristic (`LBLumoService.java`) |
| 4098 (0x1002) | `af121002-31d4-48e8-a1f8-5c09c020ae42` | Options characteristic (`LBLumoService.java`) |
| 513 (0x0201) | `af120201-31d4-48e8-a1f8-5c09c020ae42` | Bulk transfer server control (`LBBulkTransferService.java`) |
| 514 (0x0202) | `af120202-31d4-48e8-a1f8-5c09c020ae42` | Bulk transfer server data |

- LumoBack/LumoBase service = 1 (`af120001-...`), LumoRun = 513 (`af120201-...` collision
  note: enum values overlap with bulk-transfer chars; see `LBConstants.java`).
- Standard CCCD `00002902-...` used in `LBDeviceBLE.java`.
- `LBDeviceMonitor.java` also accepts 16-bit service UUIDs from the advertising record.
